# folderblog

**A folder is a blog.** Write a Markdown file, save it into a folder, and a few seconds
later it is live on your site. No front matter, no build step, no commit, no deploy
command.

folderblog is a single binary that runs quietly in the background. It watches `~/Blogs`,
where every folder is its own blog, and publishes each one to GitHub Pages (or anywhere
else) whenever you save. With GitHub, even starting a new blog is one command: folderblog
creates the repository and switches on Pages for you.

It is also built to be designed by coding agents. Every blog ships with an `AGENTS.md`
contract, and a theme is nothing but templates, so an agent can build almost any design
without touching the engine.

## Features

**Writing**
- Plain Markdown files. Front matter is optional: the title comes from the first heading
  (or the filename), the date from the filename (`2026-09-30-my-post.md`) or from the
  moment folderblog first saw the file, and it never changes after that.
- Folder posts: put `index.md` and its images in `posts/my-trip/` and relative image
  paths just work.
- Pages (`pages/about.md` → `/about/`), drafts that only appear in preview, a `static/`
  folder copied as-is, and `data/` files (JSON, TOML, YAML) for templates.
- Tables, footnotes, task lists, syntax highlighting, and raw HTML are all supported.
- Deleting a file unpublishes it. Your files are only ever read, never modified.

**Publishing**
- Saves are debounced, and editor temp and swap files are ignored.
- GitHub Pages with no manual steps: repo creation, Pages setup, custom domains and
  HTTPS are handled for you.
- Also publishes to any git branch or runs any command (rsync, rclone, wrangler…).
- Each blog is independent: its own theme, settings and host, and a problem in one never
  affects the others.

**Safety and visibility**
- Every build happens in a fresh folder and only replaces the live site if everything
  succeeded. A broken template never takes your site down or half-updates it.
- Desktop notifications, `folderblog status`, and the systemd journal tell you when
  something fails. You also hear about it if your GitHub login expires, and anything
  waiting publishes on its own once you fix it.

**Design**
- Themes are Jinja templates (minijinja), with no hidden base theme.
- Any output format: HTML, JSON search indexes, templated CSS, SVG, extra feeds.
- One template can render many pages: tag pages, year archives, series and paginated
  lists.
- Per-post layouts, overridable Markdown markup, a full data model, and hand-built HTML
  pages.
- The RSS feed and sitemap are generated by the engine, so no theme can break them.
- `preview` with live reload, `check` (template errors with file:line, feed
  validation, broken links), `data` (the exact template context for any URL), and
  fixture content for testing themes against edge cases.

## Install

Packages are on the [releases page](https://github.com/ninepointlabs/folderblog/releases).
They contain a single static binary for x86_64 Linux and a systemd user service. `git`
is the only dependency.

**Arch Linux / Omarchy / Manjaro**
```sh
curl -LO https://github.com/ninepointlabs/folderblog/releases/latest/download/folderblog-bin-0.1.0-1-x86_64.pkg.tar.zst
sudo pacman -U folderblog-bin-0.1.0-1-x86_64.pkg.tar.zst
```

**Debian / Ubuntu / Pop!_OS / Mint**
```sh
curl -LO https://github.com/ninepointlabs/folderblog/releases/latest/download/folderblog_0.1.0-1_amd64.deb
sudo apt install ./folderblog_0.1.0-1_amd64.deb
```

**Fedora / RHEL / openSUSE**
```sh
sudo dnf install https://github.com/ninepointlabs/folderblog/releases/latest/download/folderblog-0.1.0-1.x86_64.rpm
```

**Any other Linux (tarball)**
```sh
curl -L https://github.com/ninepointlabs/folderblog/releases/latest/download/folderblog-0.1.0-x86_64-linux.tar.gz | tar xz
sudo install -Dm755 folderblog-0.1.0-x86_64-linux/folderblog /usr/local/bin/folderblog
```

**From source** (Rust 1.89 or newer): `cargo install --git https://github.com/ninepointlabs/folderblog`

Check it worked: `folderblog --version`.

Desktop notifications use `notify-send` (package `libnotify` or `libnotify-bin`), which
most desktops already have.

## Quick start

```sh
# 1. One time: connect GitHub (see "Preparing GitHub" below for the Client ID)
folderblog login github --client-id Iv23li...

# 2. Start the background service
folderblog install-service

# 3. Create a blog. The GitHub repo and Pages are set up automatically.
folderblog new myblog

# 4. Write
echo "# Hello, world

My first post." > ~/Blogs/myblog/posts/hello.md
```

About a minute later the post is live at `https://<your-username>.github.io/myblog/`.
The first publish of a new blog waits for GitHub's first Pages build, which usually
takes 1–2 minutes. Later posts appear within about 30–60 seconds.

To see what is going on: `folderblog status`.

Not using GitHub? Skip step 1, run `folderblog new myblog --no-github`, and set a
[deploy target](#other-hosts) in `~/Blogs/myblog/blog.toml`.

## Preparing GitHub

folderblog publishes through a small **GitHub App that you register on your own account**.
It's a one-time, two-minute form. After that folderblog can create repos and switch on
Pages by itself, so new blogs need no trips to GitHub.

Why an app of your own? The login belongs to you alone, you choose exactly what it may do,
and no third-party service is involved. folderblog talks to GitHub directly from your
machine.

### 1. Register the app

Open **<https://github.com/settings/apps/new>** (for an organisation:
`https://github.com/organizations/<org>/settings/apps/new`) and fill in:

| Field | Value |
|---|---|
| **GitHub App name** | Anything unique, e.g. `folderblog-yourname` |
| **Homepage URL** | Anything, e.g. `https://github.com/yourname` |
| **Callback URL** | Leave empty |
| **Expire user authorization tokens** | ✅ Keep ticked. Logins renew themselves and last about 6 months |
| **Request user authorization (OAuth) during installation** | Leave unticked |
| **Enable Device Flow** | ✅ **Tick this.** It is how `folderblog login` works |
| **Webhook → Active** | ❌ **Untick** |

**Repository permissions:**

| Permission | Access | Why |
|---|---|---|
| **Administration** | Read and write | Create a repo for each new blog |
| **Contents** | Read and write | Push the built site |
| **Pages** | Read and write | Switch on Pages, set custom domains and HTTPS |
| **Metadata** | Read-only | Required by GitHub (selected automatically) |

Leave every **Account permission** at *No access*.

**Where can this GitHub App be installed?** → **Only on this account**.

Click **Create GitHub App**. On the page that opens, copy the **Client ID** (it looks like
`Iv23li…`). You don't need a client secret or a private key, so don't generate them.

### 2. Install it on your account

On the app's page, click **Install App** in the left sidebar, then **Install** next to
your account. Choose **All repositories**, because folderblog creates new repositories
for new blogs and the app needs access to them.

> **What this allows.** With these settings, the login stored on your machine can create
> and delete repositories on your account. It is kept in `~/.config/folderblog/github.json`,
> readable only by you, and expires unless folderblog renews it. Treat that file like
> an SSH key. You can revoke the login at any time (see below).

### 3. Log in

```sh
folderblog login github --client-id Iv23li...
```

folderblog shows a code. Open <https://github.com/login/device>, enter it, and
approve. You only pass `--client-id` the first time; it is remembered.

```
Open https://github.com/login/device and enter the code:  4DC2-EA36
logged in to GitHub as yourname; this login lasts about 181 days and renews itself
```

### 4. Create blogs

```sh
folderblog new myblog                                  # → https://yourname.github.io/myblog/
folderblog new yourname.github.io                      # → https://yourname.github.io/ (your user site)
folderblog new example.com --domain example.com        # → https://example.com/
folderblog new notes --repo my-notes-site              # choose the repo name
```

`new` writes the GitHub details into the blog's `blog.toml`. On the first publish,
folderblog creates the public repo (`yourname/myblog`), pushes the site to its
`gh-pages` branch and makes sure Pages serves it. You can also create a blog by copying
any blog folder into `~/Blogs` and editing `repo` in its `blog.toml`. The service picks
it up by itself.

### Custom domains

1. Create the blog with `--domain` (or add `domain = "example.com"` under `[deploy]` and set
   `base_url = "https://example.com"`).
2. Add DNS records at your domain registrar. `folderblog new` prints the exact records:
   - **Subdomain** (`blog.example.com`): a `CNAME` record pointing to `yourname.github.io`.
   - **Apex domain** (`example.com`): four `A` records: `185.199.108.153`,
     `185.199.109.153`, `185.199.110.153`, `185.199.111.153` (and optionally a `CNAME`
     for `www` → `yourname.github.io`).
3. Wait for DNS to spread (minutes to hours). folderblog sets the domain on Pages, keeps
   the `CNAME` file in place on every publish, and switches on "Enforce HTTPS" as soon
   as GitHub has issued the certificate.

Recommended: [verify your domain](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages)
in GitHub's settings so nobody else can claim it. That step is done on github.com.

### Login expiry and revoking

- Access renews itself automatically. You only log in again about every 6 months, and
  folderblog warns you a week before.
- If the login expires or is revoked, you get **one desktop notification** (then a daily
  reminder), `folderblog status` says so, and publishing pauses. Your posts keep building
  locally, and **everything waiting publishes within 5 minutes** of
  `folderblog login github`.
- To revoke: GitHub → Settings → Applications → *Authorized GitHub Apps* → Revoke. To forget
  the login locally: `folderblog logout github`.

### Private repositories

Add `private = true` under `[deploy]` before the first publish. GitHub Pages on private
repos needs a paid GitHub plan.

## Running in the background

```sh
folderblog install-service      # enables the systemd user service and starts it now
folderblog status               # every blog: last build, last publish, GitHub Pages build, login
journalctl --user -u folderblog -f
```

If you installed a package, this is the same as
`systemctl --user enable --now folderblog`. The service watches `~/Blogs`. For a
different folder, run `systemctl --user edit folderblog` and add
`Environment=FOLDERBLOG_ROOT=/path/to/blogs` under `[Service]`.

When the service starts it builds every blog once, so changes made while it was stopped
are published. Failed publishes (offline, login expired…) are retried every 5 minutes.

`folderblog status` exits with code 1 when anything is failing, so it also works in
scripts and status bars.

## Writing

```
~/Blogs/myblog/
  blog.toml     title, address, post URL pattern, where to publish, your own settings
  posts/        Markdown files, or a folder per post with its images beside it
  pages/        about.md -> /about/ ; an .html file here is rendered as its own design
  drafts/       only shown in `folderblog preview`
  static/       copied to the site root untouched (favicon, CNAME, downloads)
  data/         JSON/TOML/YAML files available to templates
  theme/        all templates and styles; this decides what the site looks like
  AGENTS.md     the theme contract for coding agents (generated)
  .blog/        folderblog's own state; ignore it
```

**A post can be just text:**

```markdown
# Why I keep a paper notebook

Every few years I try to go fully digital…
```

- **Title:** front matter `title`, else the first heading (removed from the body so it
  isn't shown twice), else the filename.
- **Address:** from the filename. `why-notebooks.md` becomes `/2026/09/why-notebooks/`
  by default (change `permalink` in `blog.toml`).
- **Date:** front matter `date`, else a filename prefix like `2026-09-30-`, else when
  folderblog first saw the file. That date is recorded and never moves, even if you edit
  the post or your sync tool touches it.
- **Excerpt:** everything before a `<!--more-->` line, else the first paragraph.

**Optional front matter** (YAML between `---` or TOML between `+++`):

```yaml
---
title: A walk on the Ridgeway
date: 2026-03-21
tags: [walking, photos]
layout: photo          # use theme/_layouts/photo.html for this post
draft: true            # keep it out of the live site
anything: you like     # passed through to templates as post.meta.anything
---
```

**Images:** put a post in its own folder (`posts/ridgeway/index.md`) with its images beside
it and write `![Chalk track](track.jpg)`. Loose files in `posts/` or `static/` work too.

**Unpublish:** delete the file, or move it to `drafts/`.

If a file has a mistake folderblog can't safely guess around (broken front matter, an
unreadable date), that blog's build stops, you get a notification, and the live site
keeps the last good version until you fix it.

## Themes and design

Every new blog gets a plain, readable default theme in `theme/`. Change anything: it is
all yours, and there is no hidden base theme.

The fastest way to redesign a blog is to point a coding agent at the blog folder:

> Read AGENTS.md, then redesign this blog as a dense magazine layout with tag pages and search.

`AGENTS.md` documents everything an agent needs: how files in `theme/` become pages,
the full template context, filters, and the commands for checking its own work. The
engine regenerates it (`folderblog agents-md --write`) and tests that it matches what the
engine actually does.

Useful while designing:

```sh
folderblog preview                    # http://127.0.0.1:4000, live reload, drafts included
folderblog preview --fixtures stress  # your theme against long titles, code, tables, images, empty lists…
folderblog check                      # template errors with file:line, feed validation, broken links
folderblog check --fixtures empty
folderblog data /2026/09/hello/       # the exact template context for that page, as JSON
```

In short:
- `theme/**/*.html` and `*.jinja` files are templates rendered to the same path, and
  everything else is copied.
- Paths starting with `_` (`_layouts/`, `_partials/`) are never published.
- A template can declare `each = "tags"` to make one page per tag (or per year, per
  series, per anything).
- `/feed.xml` and `/sitemap.xml` belong to the engine.

## Configuration (`blog.toml`)

```toml
title = "Field Notes"
base_url = "https://yourname.github.io/myblog"   # where the site lives (may include a path)
description = "Notes from the workbench"
author = "Your Name"
language = "en"
permalink = "/{year}/{month}/{slug}/"            # tokens: {year} {month} {day} {slug}

[feed]
limit = 20                                       # posts in /feed.xml (full content)

[deploy]
type = "github"
owner = "yourname"
repo = "myblog"
# branch = "gh-pages"
# domain = "example.com"
# private = false

# Optional build hooks (e.g. Tailwind). Hooks live here, never in the theme, so copying
# someone's theme into your blog can't run code.
[build]
pre = []
post = []                                        # $FOLDERBLOG_OUT is the fresh build folder

[watch]
ignore = []                                      # paths that never trigger a rebuild

[params]                                         # anything you like, for templates
tagline = "Notes from the workbench"
```

The full, always-current reference is the `blog.toml` section of each blog's `AGENTS.md`.

## Other hosts

**Any git remote / branch** (uses your normal git credentials):

```toml
[deploy]
type = "git"
remote = "git@github.com:you/site.git"
branch = "gh-pages"
```

**Anything else**: rsync, rclone, Cloudflare (wrangler), Netlify CLI, S3… The command runs
in the blog folder with `$FOLDERBLOG_OUT` pointing at the finished site:

```toml
[deploy]
type = "command"
command = 'rsync -a --delete "$FOLDERBLOG_OUT/" me@server:/var/www/blog/'
# command = 'npx wrangler pages deploy "$FOLDERBLOG_OUT" --project-name blog'
```

folderblog only publishes when the built site actually changed.

## Commands

| Command | What it does |
|---|---|
| `folderblog new NAME [--domain D] [--repo R] [--no-github]` | Create a blog in `~/Blogs/NAME` (published to GitHub Pages if logged in) |
| `folderblog login github [--client-id ID]` | Connect your GitHub App (once) |
| `folderblog logout github` | Forget the GitHub login |
| `folderblog install-service` | Run `watch` in the background (systemd user service) |
| `folderblog status [--json]` | Build/publish state of every blog, GitHub login and Pages builds |
| `folderblog watch` | The background process itself: watch, build, publish |
| `folderblog deploy [BLOG] [--force]` | Build and publish one blog now |
| `folderblog build [BLOG] [--out DIR] [--drafts]` | Build without publishing |
| `folderblog preview [BLOG] [--port N] [--fixtures SET]` | Local preview with live reload |
| `folderblog check [BLOG] [--fixtures SET]` | Find template errors, feed problems, broken links |
| `folderblog data [URL]` | Template context for a page (or list all pages) |
| `folderblog agents-md [BLOG] [--write]` | Refresh the blog's AGENTS.md |

`BLOG` defaults to the current folder. `FOLDERBLOG_ROOT` or `--root` changes `~/Blogs`.

## Troubleshooting

**Nothing happens when I save.** Run `folderblog status`. If the service is shown as
inactive, run `folderblog install-service`. Check the log with
`journalctl --user -u folderblog -f`.

**"not logged in to GitHub" / "GitHub login expired".** Run `folderblog login github`.
Pending posts publish within 5 minutes.

**"GitHub refused to start a login".** Check the Client ID, and that *Enable Device Flow* is
ticked in the app's settings.

**Creating the repo fails with 403 / "Resource not accessible by integration".** The app is
missing a permission or isn't installed. Recheck [step 1](#1-register-the-app) (Administration,
Contents, Pages = Read and write) and [step 2](#2-install-it-on-your-account) (installed
on *All repositories*). After changing an app's permissions, GitHub asks you to approve
the change on the installation page.

**The site shows GitHub's 404 for a few minutes after the first publish.** That's GitHub's
first Pages build. `folderblog status` shows its progress (`pages … building` → `built`).

**Links or styles break on `yourname.github.io/myblog/`.** `base_url` must include the
`/myblog` part. `folderblog new` sets this for you. Themes should use the URLs folderblog
provides, or the `| url` filter, rather than hard-coded `/…` paths.

**No desktop notifications.** Install `libnotify` (`notify-send`). Under the systemd
service the notification needs your desktop session's environment. Most desktops export
it; if not, add `systemctl --user import-environment DISPLAY WAYLAND_DISPLAY DBUS_SESSION_BUS_ADDRESS`
to your session startup.

**A template error.** `folderblog check` names the file and line. The live site keeps its
last good version until it's fixed.

## How it stays safe

- It only ever **reads** your writing, never modifies it, so editors with the file open
  never complain.
- Each build goes into a fresh folder and swaps in only if every page rendered. A
  failed build leaves the live site exactly as it was.
- Editors that save by writing a temp file and renaming it are handled. Swap files,
  backups and sync-tool debris are ignored, and bursts of saves become one build.
- Blogs build independently, so a broken blog never blocks another.
- The GitHub login is stored only on your machine (`~/.config/folderblog/github.json`,
  mode 600). It is sent to GitHub per request and never written into git config.
- Build hooks can only come from your `blog.toml`, never from a theme.

## Building from source

```sh
git clone https://github.com/ninepointlabs/folderblog && cd folderblog
cargo build --release              # target/release/folderblog
cargo test                         # engine tests, including the AGENTS.md contract
tests/e2e.sh                       # watch + two blogs + local git remotes + failure/recovery
```

Release packages (static musl binary, .deb, .rpm, Arch package, SHA256SUMS):

```sh
rustup target add x86_64-unknown-linux-musl
cargo install cargo-deb cargo-generate-rpm
packaging/build-release.sh          # needs clang; makepkg for the Arch package
```

To add a new publishing target, implement `deploy::Target` in `src/deploy.rs` and add a
variant to `DeployConfig` in `src/config.rs`.
